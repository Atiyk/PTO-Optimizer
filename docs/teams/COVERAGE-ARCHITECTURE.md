# Regulated coverage: architecture

Status: Phase 0 of the "Regulated coverage" build (2026-10-30). This is the map for the
extension; `COVERAGE-SPEC.md` (Phase 1) is the contract. It extends `ARCHITECTURE.md`; the
boxes there (surfaces → capability registry → engine / AI module / DB) do not change.

Nothing here is legal advice. Every rule a customer sees carries a citation or the label
"needs verification".

## 2. Core concepts and where they live

| Concept | Representation | Code |
|---|---|---|
| **Time block** | Half-open UTC interval `[utcStart, utcStart + blockMinutes)` labelled with the site's local date and local start minute. Generated by walking real UTC instants, so DST spring-forward skips the missing local hour and fall-back repeats one (both labelled, told apart by `utcStart`). Default 30 minutes. | `engine/coverage/timeBlocks.ts` |
| **Site** | The existing `locations` row (it already has `timezone`). | schema `locations` |
| **Room / post** | New `rooms` table: site, name, kind (`room` / `post`), age group (childcare) or service (clinic). | schema `rooms` |
| **Rule pack** | Versioned JSON: jurisdiction (country, state, city) + vertical + effective dates + rules, each rule cited `{regulation, section, url, retrievedOn}` or `needsVerification: true`. Seed packs ship in `packages/engine/rulepacks/`; an org's chosen or edited pack is copied into `rule_packs` (immutable versions) and linked per site. | engine `rulepacks/`, schema `rule_packs`, `site_rule_packs` |
| **Demand** | Children (or booked-role) **counts** per room per block, from a weekly template plus dated exceptions. Counts only: never names, birthdays or anything child-identifying. | schema `demand_templates`, `demand_exceptions` |
| **Schedule** | Weekly shift templates per member + dated exceptions. Shifts are local start/end times in the site timezone and may cross midnight. | schema `shift_templates`, `shift_exceptions` |
| **Credential** | Org credential types (lead teacher, CPR, first aid, director-qualified, hygienist licence…) and member credentials with issued/expires/evidence ref/verified-by. Expired on a date → not eligible on that date. | schema `credentials`, `member_credentials` |
| **Required staff** | `required(block, room) = max(ratio requirement, role requirements)`; `present = scheduled − on leave − ineligible`; `gap = required − present`. Pure function. | `engine/coverage/requiredStaff.ts` |
| **Cover request** | The gap (room, blocks, rule broken), source (leave request / call-off / credential lapse), ranked candidate snapshot with reasons, offers, responses, outcome. Append-only `cover_events`; current state is a fold over events. | schema `cover_requests`, `cover_offers`, `cover_events` |
| **Fairness ledger** | Derived from `cover_events` of kind `filled` (cover taken, holiday cover, short-notice cover per member). Never a mutable counter. | engine `ranking.ts` input, capability `findCover` |
| **Hours worked** | Imported per member per pay period (CSV from payroll / time clock). No time clock in this build. Drives hourly sick-leave accrual. | schema `hours_worked` |

## 3. How it plugs into what exists

### Engine (pure)

- New folder `packages/engine/src/coverage/`. Days Off imports only explicit subpaths
  (`@daysoff/engine/solver/solve`, …), so its bundle is unaffected; `npm run verify:dist`
  proves it at every gate.
- **Sick-leave accrual extends the existing policy model, not a parallel one.**
  `LeavePolicy.accrual` keeps `per_hour_worked` and gains optional fields:
  `hoursSource: 'scheduled' | 'imported'` (default `scheduled`, today's behaviour),
  `annualAccrualCap`, `annualUseCap`, `frontload` (amount at plan-year start, replacing
  accrual for that year), `accrualStartsAfterDays` and `usableAfterDays` (the existing
  `waitingPeriod` covers one of these; both are needed for laws that separate "accrues from
  day 1" and "usable from day 90"), and `minimumAccrualHours` for thresholds.
  `MemberFacts` gains `hoursWorked?: { periodStart, periodEnd, hours }[]`. A policy without
  the new fields projects exactly as before (existing tests stay untouched).
- **The team planner keeps its interface.** `TeamPlanInput.rules` stays day-level
  `CoverageRuleInput[]`. Phase 5 adds an optional `blockCoverage` callback/precomputed
  per-day slack derived from the block model; when absent (every MVP org), the planner is
  byte-for-byte the same code path.
- The MVP's day-level `coverage.ts` stays for non-regulated orgs. Regulated orgs (a site
  with a rule pack) get block-level coverage; `draftLeaveRequest` and
  `decideLeaveRequest` add a `blockCoverage` field to their output (additive) and D4
  auto-approval treats any new ratio/role gap as a hard fail.

### Capability registry

All new actions are registry entries using the same pipeline (validate → authorize →
autonomy → handler → output validation → audit). Tool budget: the MVP exposes 17 tools
over MCP. Adding the seven member/manager-facing ones (`getCoverage`, `findCover`,
`requestCover`, `respondToCover`, `reportCallOff`, `getCoverageForecast`,
`draftRulePackFromText`) gives 24 ≤ 25. Admin capabilities (`saveRulePack`,
`manageSchedule`, `manageCredentials`, `importHoursWorked`) are UI + REST only.

New scopes (additive; existing tokens keep their scopes):

| Scope | Given to | Meaning |
|---|---|---|
| `coverage:read` | employee+ (own schedule); manager+ (site coverage) | Coverage, gaps, schedules, credentials expiry |
| `cover:request` | manager+ | Find cover and send offers |
| `cover:respond` | employee+ | Accept or decline an offer, report a call-off |
| `rules:draft` | admin | Draft a rule pack from text |
| `payrates:read` | owner/admin only; **never** granted to tokens | Pay rates for cost-aware ranking |

Service agents may hold `coverage:read` and `cover:request`, but `requestCover` from any
agent below L3 becomes a draft a person confirms (R2), and accepting cover is people-only.

### Surfaces

- **Employee PWA** at `/m/*` inside `apps/teams` (same Next.js app, its own manifest and
  service worker, 375px first): my schedule, my balances (incl. sick hours), request leave,
  report a call-off, cover offers, my credentials.
- **Sign-in for non-Slack staff:** invite link → passkey (WebAuthn via `@simplewebauthn/server`
  and `@simplewebauthn/browser`, maintained) with an admin-issued one-time code fallback
  (hashed, rate-limited, short-lived). Slack OIDC unchanged.
- **Messaging adapter** (`src/messaging/`): `MessagingProvider.send({to, template, data})`
  with `mock` (tests, default), `slack` (existing Slack app), `webpush` and `twilio`
  (implemented, documented, inert unless `TWILIO_*` env secrets exist and the org enables
  it). Adapters hold no business logic: the capability decides who gets what; the adapter
  only delivers. Every send goes through an outbox row.

### AI module

Unchanged rules (model map, budgets, cache by content hash, mock in CI, number check).
New tasks: `rulePackFromText` (every rule carries the exact source sentence or
`not stated`; pasted text is delimited as untrusted), `explainCoverage` /
`explainRanking` / `explainSickBalance` (engine facts in, prose out, number provenance
check extended), `parseCallOff` / `parseCoverRequest` (structured drafts the engine
validates).

## 4. Schema changes (all additive)

New tables (every one has `org_id` and the org index):

`rooms`, `credentials`, `member_credentials`, `rule_packs`, `site_rule_packs`,
`demand_templates`, `demand_exceptions`, `shift_templates`, `shift_exceptions`,
`hours_worked`, `cover_requests`, `cover_offers`, `cover_events`, `member_pay_rates`,
`member_cover_prefs`, `passkeys`, `one_time_codes`, `push_subscriptions`,
`message_outbox`.

Changed tables (new nullable / defaulted columns only):

| Table | Column | Default | Why |
|---|---|---|---|
| `organizations` | `vertical` (`general` / `childcare` / `clinic`) | `general` | Labels and pack filter; `general` = MVP behaviour |
| `organizations` | `cost_aware_ranking` | `false` | Pay rates are stored only when on |
| `organizations` | `call_off_reasons_enabled` | `false` | Health-data minimisation |
| `members` | `employment_type` (`salaried` / `hourly`) | `salaried` | Sick accrual source, overtime flags |
| `members` | `phone_e164` | null | Only for the messaging adapter; never in logs |
| `leave_requests` | `source` (`request` / `call_off`) | `request` | Call-offs create a leave request |
| `webhook_endpoints` events enum | add `coverage.gap_detected`, `cover.requested`, `cover.filled`, `credential.expiring` | – | Phase 6 |

**Child data rule, enforced by test:** no table or API schema may contain a column/field
matching child names, dates of birth, addresses, guardians, allergies or any per-child
identifier. Demand is `(room, weekday|date, start, end, age_group, count)` only. A schema
test lists every column of every table and fails on a deny-list match.

**Pay rates:** `member_pay_rates` rows exist only while `cost_aware_ranking` is on
(turning it off deletes them). Read only by owner/admin through `payrates:read`, which no
token can hold. The ranking passes a **cost band** (`regular` / `overtime`), never a rate,
to anything outside the engine call, and never to the LLM.

## 5. Migration plan for live data

1. Migrations are generated by `drizzle-kit` into `apps/teams/drizzle/000N_*.sql`, one per
   phase, additive only: `CREATE TABLE`, `ADD COLUMN … DEFAULT …` (nullable or defaulted),
   new indexes. No `DROP`, no column type changes, no renames.
2. Each migration has a hand-written down script in `apps/teams/drizzle/down/000N_*.sql`
   (drop the new tables and columns) and a test that applies up → down → up on PGlite and
   asserts the MVP's tables and rows are unchanged.
3. Existing orgs get `vertical = 'general'` and no sites with a rule pack, so every code
   path checks "regulated?" (site has a pack) before using the block model. With no pack,
   `draftLeaveRequest`, `decideLeaveRequest`, auto-approval and the planner behave exactly
   as in the MVP. The MVP acceptance suite (A1–A12) runs at every gate (RC11).
4. Rollout per org is opt-in: an admin picks a vertical and a rule pack for a site.

## 6. Known MVP gaps that touch this work (from the Phase 0 audit)

- `per_hour_worked` accrues on **scheduled** hours (`workingHoursIn`), not hours actually
  worked. Fine for salaried staff; wrong for hourly sick-leave law. Fixed by the additive
  `hoursSource: 'imported'` extension above (Phase 1), not by changing the existing path.
- Coverage is day-level (`coverage_rules`: team, min present, tag, weekdays). No time of
  day, no room, no ratio. Kept as is for MVP orgs; the block model sits beside it.
- Members have free-form `tags` used for role coverage. Credentials replace tags for
  regulated eligibility (they expire and carry evidence); tags remain for MVP rules.
- No non-Slack sign-in for staff without email: the passkey + one-time-code flow is new.
- The planner's tie-break is by member id (stable per org, not across reseeds). Cover
  ranking uses the same convention: final tie-break by member id.
