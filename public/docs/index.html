URL parameter contract

The solver behind PTO Optimizer is deterministic: every control on the page round-trips through the URL's query string, and the exact same URL always produces the exact same plan — for anyone, at any time. There is no account, no session, and nothing personalised beyond what's in the URL itself. This page documents every parameter it reads, so a URL can be constructed directly instead of reverse-engineered from the UI.

A URL with none of these parameters is valid and solves with sensible defaults (today through December 31 this year, a geolocated country guess, a balanced weighting). Every parameter below is optional unless noted.

Core

ParamTypeDefaultWhat it does
cISO country code, e.g. US, GBGuessed from browser languageCountry used for public holidays.
sdstring—Subdivision (state/province) code for region-specific holidays, where the country supports it.
sdate, YYYY-MM-DDTodayDate range start.
edate, YYYY-MM-DDDec 31 this yearDate range end.
bnumber, 0–400A balance guessPTO days available (the budget the solver spends).
wnumber, 0–100, step 1030Weighting: 0 maximises total days off and ignores travel demand; 100 minimises travel demand and accepts fewer days off.
countnumber, 0–70Break-count slider position. 0 lets the solver decide; 1 is one long break; 7 is as many short breaks as the calendar allows.

Pinning and excluding specific dates

ParamTypeDefaultWhat it does
pcomma-separated datesnoneDays forced in (pinned) regardless of what the solver would otherwise choose.
rcomma-separated datesnoneDays forced out (ruled out) — never suggested, even if they'd otherwise be chosen.
bocomma-separated datesnoneBlackout days — days you can't take off at all (meetings, on-call, etc.).
odcomma-separated datesnoneOverlap days — someone else's time off, marked on the calendar for reference.

Work pattern and calendar settings

ParamTypeDefaultWhat it does
ws0 or 1Auto (by country)Week starts on Sunday (0) or Monday (1).
ww7-character binary string1111100Which days of the week are working days, Monday-first (1 = workday).
af1offEnables a compressed (9/80) schedule with an alternating day off.
afsdate—Start date the 9/80 pattern anchors to. Read only when af=1.

PTO policy

ParamTypeDefaultWhat it does
rvnumber3Days to keep in reserve (not spent by the solver).
up1offUnlimited PTO toggle — the budget (b) is ignored and the solver may spend freely.
npnumber14Notice period, in days, used to calculate each recommendation's request-by date.
ac1offEnables monthly accrual modelling.
amnumber1.25PTO days accrued per month. Read only when ac=1.
ex1offEnables an expiry/carryover cap on unused PTO.
xddate—Expiry date. Read only when ex=1.
ccnumber0Maximum PTO days that carry over past expiry. Read only when ex=1.
pc1offEnables a cap on PTO days usable within a peak-season window.
pcsdate—Peak-season window start. Read only when pc=1.
pcedate—Peak-season window end. Read only when pc=1.
pcmnumber5Maximum PTO days spendable inside the peak-season window. Read only when pc=1.

Sabbatical Planning (/sabbatical)

A separate, smaller parameter set — one contiguous block placed once, not a budget spent across many breaks. c and s above are shared in spirit (country and a start date) but are namespaced separately here since the two tools solve different problems.

ParamTypeDefaultWhat it does
cISO country codeGuessed from browser languageCountry used for public holidays.
lennumber, 1–524Sabbatical length, in weeks.
sdate, YYYY-MM-DDTodayEarliest eligible start date.
ptonumber, 0–155PTO days to add, extending the block (spent before unpaid leave).
unpaidnumber, 0–520Unpaid leave, in weeks, to add on top of PTO once it's exhausted.
seldate, YYYY-MM-DDThe top-ranked placementWhich of the three ranked placements is selected, by its own start date (not a list position, since re-ranking can reorder the list).

Worked examples

Default US plan, 15 PTO days, through the end of 2026:

https://pto-optimizer.app/?c=US&s=2026-10-27&e=2026-12-31&b=15

UK plan weighted toward quieter travel weeks (w=80), with December 25–26 pinned in and one Friday ruled out:

https://pto-optimizer.app/uk?c=GB&s=2026-10-27&e=2027-01-31&b=20&w=80&p=2026-12-25,2026-12-26&r=2026-11-27

Germany, unlimited PTO, one single long break (count=1), a 4-day blackout window:

https://pto-optimizer.app/germany?c=DE&s=2027-06-01&e=2027-08-31&up=1&count=1&bo=2027-07-04,2027-07-05,2027-07-06,2027-07-07

A 6-week US sabbatical, eligible from June 2027, 5 PTO days plus 2 weeks unpaid leave added:

https://pto-optimizer.app/sabbatical?c=US&len=6&s=2027-06-01&pto=5&unpaid=2

Every one of these three URLs reproduces the identical plan every time it's opened, by anyone, since nothing outside the parameters themselves (no account, no stored preference) affects the result. See data-sources.json for where the underlying holiday and travel-demand data comes from, and the privacy page for what is and isn't collected.
